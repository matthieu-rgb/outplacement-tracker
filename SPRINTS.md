# SPRINTS.md

Work plan divided into 3 sprints. Each sprint produces concrete, testable deliverables.

---

## Sprint 1 : Business foundations

**Objective**: produce the full set of business specifications and base assets, ready to be consumed by subsequent sprints.

**Deliverables**

- [x] `specs/sharepoint_schema.md` : complete schema of SharePoint lists (columns, types, default values)
- [x] `specs/forms_questions_de.md` : exact questions for the onboarding and monthly review Forms in German
- [x] `specs/forms_questions_en.md` : 1:1 English version
- [x] `specs/email_templates.md` : 4 email templates (J-5 invitation DE/EN, Beraterin notification J DE/EN)
- [x] `specs/word_template_structure.md` : structure of the Word template with list of content controls and their Tag values
- [x] `templates/word/transfer_mappe_template_de_spec.md` : construction spec for the DE Word template (see note below)
- [x] `templates/word/transfer_mappe_template_en_spec.md` : construction spec for the EN Word template (see note below)

**Domains involved**

- Architecture: data structure, cross-list consistency
- Microsoft 365: Forms feasibility, Word content controls compatible with Power Automate
- Technical writing: form questions and emails, German professional register
- Security and DSGVO: review of collected data (minimisation, no unjustified PII)

**Note on Word templates**: binary .docx files cannot be generated by an agent without a Word runtime. Detailed construction specs have been produced instead (`*_spec.md`). These specs document exactly the Content Controls, Tag values, styles, and XML structure required to build the .docx manually in Word in approximately 30 minutes. Building the actual .docx files is a Sprint 2 task (test in Dev tenant).

**Definition of done**

- All `specs/` files technically valid
- Word templates openable without error in Word and compatible with the "Populate a Microsoft Word template" Power Automate action
- No field collects unjustified personal data
- Commit `feat: sprint 1 - business specs and templates`

## Sprint 2 : Power Platform automation

**Objective**: produce the complete integration kit (implementation guides, scripts, templates, samples).
Delivered in blueprint mode without a tenant (ADR-006): Flows and Forms are documented
as Markdown implementation guides rather than importable JSON exports.

**Deliverables**

- [x] `templates/word/transfer_mappe_template_de.docx` : DE Word template with 118 Content Controls
- [x] `templates/word/transfer_mappe_template_en.docx` : EN Word template with 118 Content Controls
- [x] `templates/word/build_templates.py` : template generation script
- [x] `sharepoint/lists_schema.json` : declarative schema of the 3 SharePoint lists
- [x] `sharepoint/setup_lists.ps1` : idempotent PnP PowerShell script
- [x] `forms/forms_construction_guide.md` : step-by-step guide for creating the 4 forms
- [x] `power_automate/Flow_1_Invitation_J-5.md` : implementation guide for the J-5 Flow
- [x] `power_automate/Flow_2_Generation_PDF.md` : implementation guide for the PDF Flow
- [x] `power_automate/IMPORT_GUIDE.md` : global setup guide (7 steps)
- [x] `samples/sample_pdf_output_de.pdf` : DE cumulative PDF - Max Mustermann - 3 fictitious months
- [x] `samples/sample_pdf_output_en.pdf` : EN cumulative PDF - John Doe - 3 fictitious months
- [x] `samples/build_samples.py` : Python sample generation script
- [x] `docs/DECISIONS.md` : ADR-006 (blueprint delivery without tenant)

**Note ADR-006**: blueprint delivery mode. Power Automate Flows and Microsoft Forms
are documented as Markdown implementation guides rather than importable JSON exports.
Decision justified by the absence of a Dev tenant within the sprint deadline.
Actual deployment by the client's M365 administrator following the guides: 2 to 4 hours.

**Domains involved**

- Microsoft 365: Flow and Forms implementation guides, PnP script
- Architecture: cross-list consistency, Tag values, Power Automate expressions
- Security and DSGVO: anonymised fictitious data, no real PII in guides

**Definition of done (adjusted by ADR-006)**

- Implementation guides valid and consistent with the SharePoint and Word specifications
- Python scripts executed and validated (118 Content Controls per template, PDFs generated)
- No personal email address or real PII in the guides or samples
- Commit `feat: sprint 2 - integration kit (templates, scripts, implementation guides)`

---

## Operating rules

1. **No sprint skipping.** Sprint N+1 does not start until sprint N is done.
2. **No deliverable added mid-sprint.** Any new idea goes into `BACKLOG.md`.
3. **Each critical deliverable undergoes a review** in its relevant domain.
4. **Any delay or blocker** is documented in `docs/DECISIONS.md` (new ADR if necessary).
